# Pulse Messenger

Мессенджер на React и Firebase Realtime Database: регистрация по email, эмодзи-аватары, личные чаты и каналы с уникальными @username, подпиской по кнопке, перепиской в реальном времени, аудио/видеозвонками и админ-панелью с галочками. Встроенный бот техподдержки отвечает на частые вопросы; его история сохраняется в браузере. Подарки и монеты работают без Cloud Functions и без Blaze.

## Запуск

```bash
npm install
npm run dev
```

Firebase Web config уже добавлен в `src/firebase.js`. В Firebase Console включите:

1. **Authentication → Sign-in method → Email/Password**.
2. **Realtime Database** в регионе `europe-west1`.
3. В разделе Realtime Database → Rules опубликуйте `database.rules.json`. Правила проверяют администратора по Firebase custom claim, закрепляют уникальность username каналов, ограничивают каталог подарков и отправку контактам, разрешают забирать один подарок только один раз и проверяют формат голосовых сообщений. Почасовое начисление +10 монет защищено правилами базы.

Для звонков нужны разрешение на микрофон/камеру и HTTPS (GitHub Pages подходит). STUN используется для базового соединения; в некоторых сетях для надёжных звонков понадобится собственный TURN-сервер.

## Администратор и значок

Назначить начального администратора может только владелец Firebase-проекта через Firebase Admin SDK. Скачайте service-account JSON из Firebase Console → Project settings → Service accounts, затем локально выполните:

```bash
npm install firebase-admin
node scripts/set-admin.mjs admin@example.com path/to/service-account.json
```

Не добавляйте service-account JSON в репозиторий или в клиентское приложение. Выйдите из приложения и войдите снова. После этого появится панель управления: владелец админки выдаёт и снимает галочки, выдаёт подарки и назначает модераторов. Модераторы могут отправлять предупреждения и блокировать аккаунты на 1, 3, 6, 12 или 24 часа; бан модератора может снять владелец админки. Правила Realtime Database разделяют права и не позволяют модераторам назначать роли или управлять другими модераторами. Пользователь видит причину и срок блокировки при следующем входе. Изображение значка находится в `public/verifybadge.png`.

## Публикация на GitHub Pages

React/Vite исходники находятся в архиве `pulse-source.zip`. GitHub Actions распаковывает его, собирает сайт и публикует GitHub Pages. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**. В Firebase Authentication → Settings → Authorized domains добавьте домен GitHub Pages.

## Подарки и монеты без Blaze

В каталоге 9 подарков. Цены в монетах повторяют начальные цены Telegram Stars для соответствующих подарков; Кубок алгоритма получил отдельный коллекционный уровень, так как его раздавали участникам олимпиады. Получатель забирает около 60% цены подарка в монетах один раз. Покупка и доставка проходят через Realtime Database, администратор может выдавать подарки бесплатно. +10 монет начисляются за каждый полный час; пропущенные часы догоняются при следующем входе. Cloud Functions и план Blaze не используются. Уже полученные подарки остаются в истории.

После изменения правил откройте Realtime Database → Rules, вставьте актуальное содержимое `database.rules.json` и нажмите **Publish**. Затем GitHub Actions пересоберёт и опубликует сайт.

## Безопасность

Firebase Web API key предназначен для клиентского приложения. Ограничения доступа обеспечивают Authentication и правила Realtime Database. Не публикуйте service-account JSON и другие приватные ключи.
